## 1. 一句话定位

Harness VLA 把冻结的 VLA 封装成原语库里唯一的学习原语 VLA_ACT，与六个解析原语（MOVE_TO、MOVE_POSE、ROTATE_WRIST、ROTATE_PITCH、SET_GRIPPER、RELEASE；RoboCasa365 另加 NAVIGATE_TO、MOVE_BASE）放在同一个 JSON 接口下，由一个 coding agent 规划器（Codex 或 Claude Code）以 REPL 方式逐条调用；规划器不写动作，只选原语并绑参数。它不改权重、不扩技能库，而是通过一次"参考种子"上的探索，把成功的原语序列存成**任务专属记忆**（去掉具体坐标、换成符号化感知查询的 JSONL 轨迹 + 审计 JSON），把跨任务的经验存成**全局记忆**（成功规则与失败模型），部署时检索并用实时 RGB-D 重新 grounding。LIBERO-Pro 总体 82.4%（Claude Code）/ 72.1%（Codex），对比冻结 VLA 直接执行 50.0%、此前最强的 RATS 43.8%；RoboCasa365 57.1%（Codex）对比 RLDX-1 30.0%；RoboTwin C2R 58.4% 对比 LingBot-VLA 50.4%。

## 2. 要解决的问题

论文的诊断是"两种范式各把过多责任分给了错误的组件"：单体 VLA 要在一个策略里同时承担语言 grounding、长程组合与低层控制，于是在语义重定向、目标重绑定、布局变化、不稳定接触这些部署扰动下退化——图 3 里 πRLinf 在指令改了之后仍重复训练时的行为，布局变了仍把物体往训练时的位置搬；coding agent 则要用人工或 agent 生成的 API 去实现物理上精细的交互，而纯解析原语搞不定不规则抓取、受限放置与铰接物体。答案是不对称分层：解析原语穿越扰动，VLA 只在训练分布有信息量的局部接触区域内被调用。

## 3. 方法

**执行循环。** 环境每回合给出 RGB、共对齐的度量深度图与本体状态；规划器读观测、任务描述、两类记忆，输出一个 JSON 原语调用；原语在环境里跑到内部后置条件满足才返回控制权（VLA_ACT 带任务条件 prompt、`max_chunks` 与早返回谓词 `stop`）。控制通过文件中介：写 `command.json`，等 `done_NN.flag`，读新的 `state_NN.json`、日志、图像、深度、世界地图，再决定下一条——和 coding agent 的 REPL 完全同构。

**感知隔离。** 规划器拿不到物体位姿等特权信息：它从 RGB 里认出目标、在可见表面选多个像素、索引预计算的世界地图取三维坐标、取中位数、避开边缘/反光/背景，并在机器人、相机、物体、抓取状态任一变化后重新定位。

**两阶段生命周期。** 探索自举阶段只在一个参考种子（s0）上进行，规划器独享 RESET 原语与宽松的时间预算，反复尝试不同的预定位顺序、接触前位姿、VLA_ACT 的调用时机与早返回阈值；成功后把验证过的原语序列序列化为 JSONL，把具体坐标替换为符号化感知查询，连同审计 JSON（结果、步数、策略笔记、失败观察、终态摘要）存入任务专属记忆，再把可泛化的启发式提交到全局记忆。部署评估阶段禁用 RESET、大幅缩短步数预算，规划器检索 s0 的轨迹并用实时 RGB-D 重新 grounding，参考全局记忆的规则执行。

**记忆的具体形态（附录 E）。** 任务专属记忆是"任务级解法骨架而非开环轨迹"：记录原语顺序、解析与 VLA 调用的选择、VLA 调用的数量与位置、感知 → 预定位 → 接触 → 搬运 → 释放 → 验证的转折点；审计 JSON 里有"不要复用参考 xyz""用基准成功信号验证放置"这类笔记。全局记忆是任务无关的，论文给的样例：

- 成功规则：接触密集阶段（不规则抓取、固定装置交互）用 VLA 原语；稳定抓取后长距离搬运与精确放置用解析运动。
- 失败模型：夹爪闭合但物体没有随末端移动 → 判定为空抓，重新定位并重新预定位后再试。
- 失败模型：不要仅凭视觉接近就终止；检查基准成功信号与最新执行记录。

记忆是**在交互中迭代构建**的：每个原语之后规划器把结果分类为进展、可恢复失败、不可恢复失败；成功轨迹存入任务专属记忆，可恢复失败留在轨迹里并在语义摘要中解释，失败尝试作为负面证据保留并可能贡献失败模型；更短或更可靠的后续尝试会替换过程轨迹，早先的失败观察则作为未来规划的约束保留。

## 4. 实验结果与口径

- **协议**：每任务 s0 只用于自举，报告用 s1-s10 十个留出种子；LIBERO-Pro 80 任务 800 次 rollout，RoboCasa365 340 次，RoboTwin C2R 50 任务 × 5 种子 250 次；成功由基准提供的二元谓词判定，原语级后置条件不作替代。
- **标准 LIBERO**：Harness VLA（CC）96.0%（384/400），VLA_ACT 内的冻结 πRLinf 直接执行 95.3%——不损失分布内性能。
- **LIBERO-Pro**（指令重定向 T / 位置交换 S）：OpenVLA 0.0、π0 0.3、π0.5 11.0、AtomVLA 6.3、Cap-X 18.2（六格）、RATS 43.8（六格）、πRLinf 50.0、Harness VLA（Codex）72.1、（CC）82.4。**头条的 +38.6 个百分点是 82.4 对 RATS 的 43.8**；对同一冻结 VLA 直接执行（50.0）是 +32.4。
- **RoboCasa365**：RLDX-1 30.0，Harness VLA（Codex）57.1、（CC）48.6 → +27.1（Codex）；Atomic-Seen 92.0 / Composite-Seen 61.0 / Composite-Unseen 13.8。
- **零样本 LIBERO-Pro GOAL**（不检索任何记忆）：位置交换 31.0% vs Cap-X 25.6%，指令重定向 79.0% vs 16.8%；与少样本的 Goal-S 87.0% / Goal-T 87.0% 对照，说明记忆的价值主要在空间扰动——语义重绑定靠规划器在线推理就够，空间预定位要靠探索学来的原语组织。
- **RoboTwin C2R**：从干净设置获得的任务专属记忆直接迁到随机化实例，58.4%（CC）/ 58.0%（Codex）vs 冻结 LingBot-VLA 50.4%（+8）。
- **三个机制分析**：规划器级语义重新 grounding 恢复任务条件化（图 3）；限制每回合允许的 VLA 调用数，成功率在前几次调用后快速上升然后饱和（图 4）——VLA 被稀疏调用，但可重新预定位与重试是鲁棒性的核心；完成归因（图 6）：LIBERO-Pro 多数成功由接触后的解析原语完成，RoboCasa365 与 RoboTwin 更多在 VLA 原语内完成。

## 5. 局限

1. **论文自述**：规划器与 VLA 之间是开环反馈（VLA 不知道规划器为什么调用它）；没有用环境奖励或人类偏好做联合微调（提出未来用 GRPO）；缺少细粒度图像描述，杂乱长程场景的结构推理受限；未来方向是与 ASPIRE 式技能发现结合——在重复的原语组合暴露出缺失抽象时提出、验证并准入新技能。
2. **验证器是基准谓词**：规划器在探索与部署中都能读到基准的成功信号（提示词模块"优化基准谓词而不是视觉猜测"，全局记忆规则"检查基准成功信号"）。这在仿真里是合理的实验控制，在真机上不存在——把它搬到真机，第一件要补的就是独立验证器（notes/12、17、19）。
3. **感知靠预计算世界地图**：深度图到三维坐标的映射在仿真里精确，真机 RGB-D 的噪声、反光与遮挡会直接进入 MOVE_TO 的参数；论文的"多像素取中位数、避开边缘"规则是缓解而非解决。
4. **全部仿真**；规划器是前沿 coding agent（Codex / Claude Code），每回合一次调用，成本与延迟未报告；Codex 与 CC 在不同基准上互有胜负（LIBERO-Pro CC 高 10 个点，RoboCasa365 Codex 高 8.5 个点），说明 harness 收益依赖规划器基座——Harness Updating ≠ Harness Benefit（notes/42）。
5. 自举需要每个任务一次参考种子探索（宽松预算 + RESET）；新任务族的零样本性能在空间扰动下降到 31%。

## 6. 关系定位

Harness VLA 与 RHO（notes/03）是 T15 的两半：RHO 优化代码策略仓库，Harness VLA 优化 VLA 的调用规则；两者都在 LIBERO-Pro 家族报数，却从未在同一原语与同一 VLA 上组合（报告开放问题第 3 条）。它对 BATON"VLA 原语没有进入条件"（notes/14）的回答是把进入条件藏在"预定位到 VLA 兼容的局部状态"里；与 RoboHarness 的 Memory Bridge（notes/24）、AtomBridge 的过渡动作同源。ENPIRE 的 RoboCasa365 混合方案（代码做 hover pose、VLA 做接触，notes/06）是同一分工的 autoresearch 版本；RoboCurve 的 GPT-6 Astra 演示（notes/44）则是去掉 VLA_ACT 之后只剩解析原语的版本，其 10% 的插入成功率正是本文要用 VLA_ACT 填的洞。全局记忆的"迭代构建 + 失败作为负面证据保留"与 SkillOpt 的拒绝编辑缓冲（notes/05）、AgenticRobotics 的证据分级技能库（notes/08）是同一思想。

## 7. 延伸批判

+38.6 这个头条数字最需要的对照是同一冻结 VLA 加"同样 VLA 调用预算的简单重试"能拿多少：图 4 显示成功率随允许的 VLA 调用数上升后饱和，说明一部分收益就来自"多试几次"，规划器的贡献应以超过重试曲线的部分计——论文没有给这条曲线的重试基线。第二，记忆的可迁移性：从 LIBERO-Pro 学到的全局规则能否直接用于 RoboCasa365 的同一 VLA？附录说全局记忆是任务无关的，但跨基准的迁移实验没有报告；如果不能迁移，"不扩张技能库"只是把技能库换成了规则库，规模问题换了对象（SkillGLoW 对文本技能"塌缩 vs 膨胀"的诊断，notes/07）。第三，也是对真机最重要的一点：这套系统把"成没成"的判断外包给了基准谓词，于是它在仿真里的可靠性有多少来自一个真机不存在的完美验证器，需要一次把验证器换成 AGM/PRIMO R1 式独立判断的重跑才能知道。这三条批评都不否定它的核心贡献——它是"冻结基座 + 外围学习"范式最完整、最可审计的一篇实现。
