# 44 · RoboCurve 的 GPT-6 Astra 演示与"Agent 当遥操作员"的数据引擎：解读与方案

> 来源：罗清雨《RoboCurve：GPT-6 Astra 直接控制机器人》（知乎，转写见 `sources/zhihu_robocurve_gpt6_astra_transcript.md`）；RoboCurve 第三方测试（经知乎与具身纪元文章转述，原始报告本次检索未取得）
> 所属主线：T2、T10、T13、T15、T23、T24 · 相关解读：notes/02（CaP-X）、06（ENPIRE）、18（VERITAS）、20（Harness VLA）、26（双系统）、29（Q-Planning）、31（RoboClaw）、33（RoboGene）
> 本篇同时回答一个实践问题：观察到"用 GPT-6 Astra 采数据集非常强"之后，怎样把它做成一条可靠的数据引擎，而不是一个昂贵的演示。

## 1. 这个演示到底是什么

RoboCurve 让 GPT-6 Astra 在同一个 agent policy 下直接控制 YAM 双臂：模型看相机与本体状态，输出 Cartesian EEF waypoint / 工具调用，IK 与底层控制器执行。用本仓库的坐标系定位，它**不是 VLA**，而是三样已知东西的组合：

- CaP-X 分层评测里"高层原语 + 多轮交互"的那一格（notes/02）：动作接口是设计者给的宏（移到某点、开合夹爪），agent 只做选择与参数化。
- Harness VLA 去掉 VLA_ACT 之后剩下的部分（notes/20）：只有解析原语，没有接触密集的学习原语。
- ENPIRE 在 RoboCasa365 上混合方案的前一半（notes/06）：代码/agent 负责几何确定的阶段（识别、接近、抓取、移到目标上方），本应交给 VLA 的接触阶段（插入）这里没有人接手。

三组数字（20 次试验/任务）：block → bowl，Fable 5 1/20（8.2 min）、Fable 5.1 8/20（6.8 min）、GPT-6 Astra 19/20（2.5 min），每次运行 2.1K tokens 对比 Fable 5.1 的 12.9K；圆形拼图插入，三者 0% / 10% / 10%。文章总结的失败模式是：identify ✓、approach ✓、grasp ✓、move above target ✓、precise insertion ✗。

三个判断：

1. **模型升级提升的是 grounding、规划与纠错的效率**，不是控制能力。token 减少约 6 倍、时间减少约 2.7 倍、成功率从 40% 到 95%，说明更强的模型用更少的推理就把简单任务做对了；这是 T1/T2 主线的一致结论（可靠性瓶颈在 grounding 与验证，不在规划）。
2. **10% 的插入成功率是已知边界的再发现**。CaP-X 已经量化过"抽象撤除则成功率下降"，Harness VLA 的摘要直接写"纯解析原语难以处理不规则抓取、受限放置与铰接物体交互"。GPT-6 与 Fable 5.1 在插入上同为 10%，恰好说明这个瓶颈不在模型——再强的 VLM 也不能用开环 waypoint + IK 解决毫米级的接触对齐。
3. **口径提醒**：20 次试验的 95% 与 40% 之差是显著的，但 10% 对 10%（各 2/20）没有任何区分力；2.5 分钟一条是采数据可以接受、实时控制完全不能接受的速度；Fable 与 GPT-6 的差距里含 harness 因素——ROSClaw 发现执行层设计比 prompt 措辞更影响完成率（notes/36），RoboCurve 的原语接口与 prompt 是否对三个模型做了同等调优，报道未说明。

## 2. 为什么它作为数据引擎比作为控制器更有前途

演示本身的三个"缺点"——慢、贵、只会几何阶段——对数据采集全不致命，甚至是优点：

- **慢而准不要求实时**。采数据的约束是每条示范的成本与质量，不是控制频率。2.5 分钟一条成功示范，配上自动复位与多台并行，吞吐可以接近人类遥操作；而它不需要人。
- **自带语义标签**。人类遥操作只产生动作，agent 采集同时产生推理轨迹、子目标文本、物体 grounding、失败诊断——正是 Temporal GRPO 需要的阶段标签（notes/32）、PRIMO R1 需要的进度真值（notes/17）、AGM 需要的子目标序列（notes/12）、以及文章说的"Ego 数据最有价值的前半段：任务理解、affordance、技能组合、状态变化预测"。
- **有先例**。VERITAS 用验证过的自主 rollout 微调策略，50 条自主轨迹的效果与 50 条人类示范相当（70% vs 65%，notes/18）；ManiAgent 用 agent 系统为 VLA 生成训练数据（notes/35）；Guava 把 harness 释放的能力蒸馏进 4B 模型（notes/24）；RoboGene 用 agent 生成多样任务采了 18k 轨迹（notes/33）；ENPIRE 让 agent 直接跑训练（notes/06）。"GPT-6 采数据"是一条已经有多个数据点的路——从慢而强的专家向快而窄的策略蒸馏。
- **经济学**。2.1K tokens 一次运行的模型成本以分计；瓶颈转移到机器人时间与场景复位——RoboClaw 的 EAP（人工时间 -53.7%，notes/31）与 ENPIRE 的 EN 模块解决的正是这一项。

## 3. 直接拿 agent 采的数据训 flow head 会遇到的六个问题

1. **轨迹形态不对**。waypoint 序列执行出来是分段直线、走-停-走、速度保守；人类示范是连续、平滑、速度分布宽的。用前者训 flow / diffusion head，学出的策略会抖、会慢、会在 waypoint 处停顿——分布本身就是错的。
2. **覆盖偏差集中在最有价值的地方**。agent 恰恰在接触段失败率最高，成功示范里插入段几乎没有；训出的 head 学会 approach 学不会 insertion，把演示的失败模式原样继承给下游策略。
3. **自我评判**。如果用 GPT-6 自己判断"成功了没有"再决定保留哪条，数据集会带上模型自己的盲区（Lil'Log 的弱评估器、具身纪元的"无法验证的变化只能叫变化"）。
4. **多样性塌缩**。同一 prompt 下 agent 的策略高度一致（ENPIRE 里多个 agent 反复试相同想法，notes/06）；数据集需要的场景、物体、路径多样性不会自动出现。
5. **时间尺度不对齐**。agent 的决策约 0.1-1 Hz，动作在 IK/控制器的 30-1000 Hz 产生；如果只记录 waypoint，就没有可训练的稠密动作；如果只记录关节轨迹，就丢了语义边界。
6. **安全与吞吐**。让前沿模型连续数小时自主控制真机需要 Projection（waypoint 限幅与工作空间约束，notes/23）、安全包络与审计（ROSClaw，notes/36）、接触前监控（ContactGuard，notes/33）；单机 2.5 分钟一条则需要 fleet 与自复位。

## 4. 更好的做法：Agent-as-Teleoperator 数据引擎

三条设计原则，一条九步流水线。

**原则 A：让 agent 采"意图与边界"，让控制器采"动作"。** 每条 episode 记录三层——agent 层（推理、子目标文本、工具调用序列、失败诊断）、意图层（waypoint / 目标位姿 / 夹爪指令）、执行层（控制器频率的关节与 EEF 轨迹、力/力矩、多视角图像）。训练 System-1 head 时用执行层的稠密轨迹做动作监督，用 agent 层的子目标或意图做条件——这正是文章"latent action intention → flow head"的数据基础。waypoint 之间的执行轨迹先做时间最优或最小 jerk 重参数化再执行，记录**执行后**的轨迹而不是规划的直线，这样分布问题（第 1 条）在采集时就被修正大半。

**原则 B：在 agent 失败的地方补人或补 RL，而不是丢掉。** 接触段有三种补法，成本递增、自动化程度递增：

- 稀疏人类接管（HG-DAgger 式）：agent 完成识别、接近、抓取、移到目标上方，人只接管最后几厘米的插入。人力从"整条示范"降到"一小段"，而这一小段正是数据集最缺的部分。
- 残差 RL：以 agent 停在"目标上方"的状态为起点、以 agent 的自动复位为循环，用 Foresight Residual RL 式的残差策略学插入（notes/14）；agent 负责把机器人反复带到同一个起始分布，这是真机 RL 最贵的部分（TwinRL 的发现：探索空间受起始分布约束，notes/30）。
- 闭环接触原语：给 agent 一个螺旋搜索 + 力控插入的解析原语，或 Harness VLA 意义上的 VLA_ACT（notes/20）。这是自举——先抬高原语抽象换取成功插入的稠密数据，再用这些数据训 head。

**原则 C：验证器与采集器分离。** 成功判定用独立的物理证据（点跟踪、跨视角比较、力信号，AGM 式，notes/12），不用 GPT-6 自评；用 PRIMO R1 式的过程判断给阶段标签（notes/17）；**失败轨迹也保留并标注失败阶段**——Q-Planning 证明同批 rollout 里失败样本让真机成功率从 55/30% 提到 90/80%（notes/29），Temporal GRPO 的阶段级信用分配需要"哪一阶段失败"的标签（notes/32）。

九步流水线：

1. 任务与场景生成：RoboGene 式多样性驱动 + 物理可行性自反思的任务生成（notes/33），真机做物体与布局随机化，仿真孪生里做域随机化（DrEureka，notes/08）。
2. Agent 采集：原语库固定且小（grounding、MOVE_TO、抓取、释放、闭环插入原语），agent 做选择与参数化；多模型或多 prompt 采样提高路径多样性。
3. 三层记录 + 轨迹重定时（原则 A）。
4. 独立验证 + 阶段标签（原则 C）；失败轨迹标注失败阶段后入库。
5. 接触段补齐（原则 B），按任务难度选人、RL 或原语。
6. 自复位：RoboClaw 的 EAP 让"恢复现场"本身成为反向任务的示范（notes/31），一次采集得到正反两条数据。
7. 蒸馏训练：System-1 head 以子目标/意图为条件；或端到端 VLA 用语言标注的稠密轨迹训练。
8. 评测：与等量人类示范做 VERITAS 式等价检验（notes/18）；接触段成功率单独报告；动作平滑度（jerk）与执行时间单独报告。
9. 迭代：把训好的 head 作为 VLA_ACT 暴露给 agent（Harness VLA），采更难任务的数据——每一轮扩大 agent 能完成的任务集，数据集覆盖随之外推。这就是具身纪元矩阵里"训练时自迭代 + 自动研究"两格的组合，也是讲稿公式里 $z$ = 数据集与 head、$A$ = 采集 agent、$r$ = 独立验证器的实例。

度量：每小时成功示范数、每条成功示范的成本（token + 机器人时间 + 人工秒数）、接触段覆盖率、下游策略成功率相对等量人类示范基线、轨迹多样性（路径/策略熵）、机器人利用率（MRU）。

## 5. 对"接一个 flow head"提法的评价

方向正确——它就是双系统（notes/26）——但两处要补。第一，接口：latent intention、文本子目标、waypoint 序列、原语调用，四种接口的可训练性与可解释性不同；PonderPounce 用一个带"年龄"的认知 token（notes/11），Cortex 用 32 个规范原语（notes/24），Harness VLA 用 VLA_ACT 调用。以原语调用为接口最容易先跑通（agent 已经在这样输出），以 latent intention 为接口需要专门的对齐训练。第二，head 的数据从哪来——文章没有回答，第 4 节是本篇的答案。另一个风险是把 GPT-6 放进 30-100 Hz 循环：延迟与成本都不允许，正确形态是异步——慢系统只在子任务边界介入（StreamVLA 的完成态门控），快系统知道自己在用多旧的指令（PonderPounce 的年龄字段）。

文章的最后一句判断——Ego 数据的价值偏向前半段（任务理解、affordance、技能组合、状态预测），精准 motor policy 靠机器人数据/仿真/RL 补——与本仓库 I2 完全一致：语义与组合能力可以从通用模型来，接触能力必须从物理数据来。数据引擎的意义正是把两者的采集分开：前半段由 agent 免费产出，后半段用最少的人力或 RL 补齐。

## 6. 最小可行实验

1. **等量对照**：同一任务，50 条 GPT-6 agent 采集并经独立验证的示范 vs 50 条人类遥操作示范，训同一 flow head；报告成功率、接触段成功率、jerk 与执行时间。若 agent 数据在几何阶段相当、在接触段显著落后，即验证第 3 节第 2 条。
2. **覆盖修补消融**：agent-only 数据 vs agent + 人接管最后 5 cm vs agent + 闭环插入原语，三个数据集训同一 head，比较插入成功率与人工秒数——回答"每条示范的人力可以压到多少"。
3. **自举课程**：round 0 用解析原语采数据训 head；round 1 把 head 作为 VLA_ACT 给 agent，采更难任务；两轮后与 round 0 比较任务覆盖与成功率——检验"抬高原语抽象换低层数据"是否单调改进（对应 ASPIRE 的库规模曲线，notes/04）。

## 7. 口径与局限

- 全部数字来自知乎文章与具身纪元文章对 RoboCurve 测试的转述，原始报告未取得；插入任务的试验数（具身纪元写 2/20）与知乎的 10% 一致，但样本量小到无法区分模型。
- "2.1K vs 12.9K tokens"是效率指标，不是能力指标；时间数字包含推理与执行两部分，未拆分。
- 第 4 节的流水线是设计方案，其中已有实证的环节（自复位、独立验证、失败样本价值、agent 生成任务、agent 数据 ≈ 人类示范）各有单篇论文支撑，把它们串成一条线的完整实验本次检索未见。
