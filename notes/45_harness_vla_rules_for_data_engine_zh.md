# 45 · Harness VLA × Agent 数据引擎：把"规则记忆"加进采集 agent

> 承接 notes/44（RoboCurve GPT-6 Astra 演示与 Agent-as-Teleoperator 数据引擎）与 notes/20（Harness VLA 全文解读）。问题：Harness VLA 的任务专属记忆与全局记忆（成功规则、失败模型）能否作为 agent 数据引擎的互补层，以及具体加哪些规则。
> 所属主线：T10、T15、T23、T24

## 1. 为什么 Harness VLA 正好是数据引擎缺的那一层

notes/44 的数据引擎有两个未解决的工程问题：agent 在每个新场景都要从头推理（RoboCurve 里 2.5 分钟一条、2.1K tokens，成本随规模线性增长），以及 agent 恰好在接触段失败、数据集在最有价值的地方留下空洞。Harness VLA 的两类记忆分别对应这两个问题：

- **任务专属记忆 = 采集配方。** 一次参考种子上的探索产出一份去坐标化的原语骨架（JSONL）+ 审计笔记（JSON）；之后每个新种子只需重新 grounding 而不重新规划。论文的少样本 vs 零样本对照给了量化依据：LIBERO-Pro GOAL 位置交换从 31.0%（零样本）到 87.0%（少样本），指令重定向从 79.0% 到 87.0%——**空间扰动下的采集成功率提升接近三倍**，而这正是数据采集中最常见的变化（同一任务、不同摆放）。
- **全局记忆 = 采集规则。** 成功规则与失败模型在论文里用于控制；在数据引擎里它们有第二个用途——**每条规则同时是一个标签函数**：空抓失败模型标出"抓取失败段"，"不要凭视觉接近终止"的规则定义了验证边界，"接触段用 VLA、搬运用解析"的规则给出阶段边界。这些正是 Temporal GRPO 的阶段（notes/32）、PRIMO R1 的进度真值（notes/17）、AGM 的子目标（notes/12）需要的东西。
- **VLA_ACT = 接触段的数据来源。** notes/44 第 4 节的三种补法之一（闭环接触原语）在 Harness VLA 里已经实现：让一个已有的 VLA 作为原语先拿到成功插入的稠密数据，再用这些数据训练更好的 head——图 6 的完成归因显示 RoboCasa365 与 RoboTwin 的成功大多在 VLA 原语内完成，说明这条来源是实的。

## 2. 规则的格式：从论文的三条样例到可验证的规则对象

论文里的规则是自然语言（附录 E.4），这对规划器够用，对数据引擎不够——规则需要能被程序检查、能统计证据、能过验证门。建议把每条规则做成一个对象：

```json
{
  "id": "R03_empty_grasp",
  "scope": {"primitive": "VLA_ACT", "phase": "grasp", "object_class": "*"},
  "condition": "gripper_closed && !object_moved_with_eef(dt=0.5s)",
  "action": ["mark_segment(failure, 'empty_grasp')", "relocalize(target)", "restage(pre_contact_pose)", "retry(max=2)"],
  "label": {"phase_boundary": "grasp_end", "outcome": "negative"},
  "evidence": {"applied": 0, "fixed": 0, "harmed": 0, "sources": []},
  "status": "candidate | validated | retired",
  "provenance": "bootstrapping seed s0 of task T, 2026-09-08"
}
```

五个字段各有来源：`scope` 与 `condition` 把论文的自然语言规则改写为可观测谓词（Harness VLA 已经在用"夹爪闭合但物体未随末端移动"这类可检测条件）；`action` 是规划器该做的事，其中新增了"交给人/RL"这一项（notes/44 原则 B）；`label` 是数据引擎独有的——规则触发即打标签；`evidence` 与 `status` 借 SkillOpt 的纪律（notes/05）：规则先是候选，在留出种子上证明"应用后成功率不降且标签与独立验证一致"才升为 validated，否则 retired；`provenance` 保证可审计（AgenticRobotics 的证据分级，notes/08）。

## 3. 起始规则集：十条

前六条改写自 Harness VLA 的做法，后四条是数据引擎需要而论文没有的。

1. **分工规则**：接触密集阶段（不规则抓取、受限放置、固定装置、插入）调用学习原语（VLA_ACT）或交给人/RL；非接触阶段（grounding、搬运、姿态调整、释放）用解析原语。来源：论文成功规则 1；用途：阶段标签。
2. **预定位规则**：任何接触原语之前，先把末端带到该原语在成功轨迹里的接触前位姿分布内（从任务专属记忆统计）。来源：Key Finding 2"staging restores a VLA-compatible local state"；用途：这就是 BATON 缺的进入条件（notes/14），以数据形式被显式化。
3. **空抓规则**：夹爪闭合但物体未随末端移动 → 标记失败段、重新定位、重新预定位、重试。来源：论文失败模型 1；用途：负样本标签，Q-Planning 需要的失败数据（notes/29）。
4. **禁止视觉终止规则**：不凭视觉接近判定完成；必须有验证信号。来源：论文失败模型 2，但把"基准成功信号"替换为**独立验证器**（点跟踪、跨视角比较、力信号；AGM/PRIMO R1）——这是论文假设与真机之间最大的缝（notes/20 第 5 节第 2 条）。
5. **重新定位规则**：机器人、相机、物体、抓取状态任一变化后重新定位目标；多像素取中位数，避开边缘、反光、背景。来源：附录 E.2；用途：真机 RGB-D 噪声下的稳健性，也决定 MOVE_TO 标签的可信度。
6. **输出纪律规则**：成功与失败的 rollout 都写审计 JSON 与命令 JSONL。来源：附录 E.1"Output discipline"；用途：这条规则本身就是数据引擎的记录层——三层记录（notes/44 原则 A）在这里落地。
7. **重试预算规则（新增）**：同一接触段的 VLA 调用不超过 k 次（论文图 4 的饱和曲线提示 k 很小），超过则交给人接管最后几厘米或触发残差 RL，并把该段标为"待补齐"。用途：把 agent 的失败转化为定向的人力/RL 投入。
8. **多样性规则（新增）**：自举阶段有意在不同种子上采用不同的预定位顺序与接触前位姿（论文探索的是"最优编排"，数据引擎要的是"覆盖"）；每个任务保留 ≥ m 条互不相同的成功骨架。用途：对抗多样性塌缩（notes/06、42）。
9. **轨迹重定时规则（新增）**：waypoint 之间以最小 jerk 或时间最优重参数化执行，记录执行后的稠密轨迹。用途：修正 waypoint 数据的形态偏差（notes/44 第 3 节第 1 条）。
10. **安全投影规则（新增）**：所有 MOVE_TO / MOVE_POSE 的目标先投影到工作空间与力/速度限制内（Projection，notes/23），VLA_ACT 带 ContactGuard 式接触前监控（notes/33）。用途：长时间自主采集的前提。

## 4. 规则怎样被学出来、怎样被验证

Harness VLA 已经给了学习机制：自举阶段的每个原语之后把结果分为进展 / 可恢复失败 / 不可恢复失败，失败作为负面证据保留，更短或更可靠的骨架替换旧骨架。数据引擎在此之上加三件事：

- **规则提议来自失败聚类**：把可恢复失败按（原语、阶段、观测特征）聚类，让规划器为每个簇写一条候选规则（SkillOpt 式的"从轨迹抽编辑方向"）。
- **规则验证用留出种子**：候选规则在 s1-s5 上启用、s6-s10 上禁用（或反之），比较采集成功率、每条成功示范的成本、以及规则标签与独立验证器的一致率；严格提升才升为 validated（SkillOpt 的选择门），并保留被拒绝的规则（拒绝缓冲）。
- **验证器只读**：规则可以演化，验证器不能——这是 Lil'Log/AHE 的原则（notes/40、42），也是 Harness VLA 靠基准谓词才成立的那部分在真机上的替代。

## 5. 与论文原设计的三处差别

| | Harness VLA（论文） | 数据引擎里的用法 |
|---|---|---|
| 目标 | 部署时的任务成功率 | 单位成本下的高质量、有标签、覆盖接触段的示范 |
| 探索 | 找一个最优骨架 | 找 m 个互不相同的可行骨架（多样性规则） |
| 验证 | 基准成功谓词 | 独立物理验证器；规则标签与验证器一致率作为规则质量指标 |
| 失败 | 负面证据，供规划器避坑 | 负样本数据 + 定向人力/RL 投入的触发器 |
| 记忆的归宿 | 供规划器检索 | 供规划器检索 + 直接转为训练标签（阶段、进入条件、成败） |

## 6. 最小可行实验

1. **配方复用的采集收益**：同一任务 20 个种子，对照"每个种子从头规划"与"s0 自举 + 骨架重新 grounding"，报告成功示范数/小时、每条的 token 成本、失败段分布——检验任务专属记忆对采集吞吐的作用（预期与论文 31% → 87% 的方向一致）。
2. **规则消融**：起始规则集全开 vs 去掉 3/4/7 任一条，报告采集成功率、负样本标签的准确率（与人工标注对照）、接触段覆盖率。
3. **验证器替换**：同一自举流程，验证器分别用基准谓词（仿真）与 AGM/PRIMO R1 式独立判断，报告假成功率——量化论文的"基准谓词"假设在真机上会付出多少代价。
